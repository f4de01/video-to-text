# Windows 本地转写实测（2026-10-23）

后续格式变更：按用户要求，当前版本仅输出 Markdown 文字稿，取消 TXT/SRT；9 项适配后的测试及 skill 校验通过。以下 TXT/SRT 实测描述保留为当时的历史记录。真实视频的既有结果已转换为 Markdown，正文未重新修复；内部时间仍用于修改记录及识别边界校验。

结论：Windows 上已跑通本地识别 → Codex 子 agent 复核 → TXT/SRT 输出 → 中间稿清理的完整流程。本次经用户授权临时使用 `gpt-6-luna / low`，默认配置未更改；默认名称 `gpt5.6 luna` 和 macOS 仍未验证。

## 环境与样本

- Windows x64；Python 3.9.25；faster-whisper 1.2.1；CTranslate2 4.8.3；PyAV 15.1.0。
- 本地多语种 base 模型，CPU INT8、beam_size=1；转写阶段启用离线标志，模型通过 prepare 提前下载。
- 使用 Windows 本机 Huihui/Zira 语音合成器生成中文、英文讲话，再使用 PyAV 封装为带黑色视频画面的 MP4。不是实际会议录音，也不是识别结果 mock。
- 中文 15.82 秒、英文 14.10 秒、中文之后接英文 28.92 秒、静音 5 秒，合计约 63.84 秒。
- 第一阶段关闭复核，结果明确标记 reviewed=false；第二阶段临时覆盖修复模型，执行真实子 agent 复核。测试样本、环境、模型和结果位于 Git 忽略的 `.test-*` 目录；第一阶段未复核结果不作为修复稿交付。

## 发现和修复

原实现直接对整段音频识别。混合样本的音频时长约 29 秒，结果却只有前 14 秒中文，英文全部遗漏。关闭 VAD 或把 beam_size 从 1 增到 5 均不能解决。直接缩短解码窗口仍出现漏转和时间越界。

改为按静音边界划分语音区域（1.2 秒静音阈值，最长约 20 秒，200 毫秒边缘保留），分别识别语言，再恢复全局时间轴。本样本的中英文均恢复。字幕时间限制在所属音频区域内，避免模型给出超过视频时长的时间点。缓存协议升级，旧版漏转结果不会被当作新版完成结果跳过。

## 验证结果

- 8 项文件协议测试通过。
- 1 项真实模型回归测试先失败后通过：断言中文存在、英文关键句及尾句存在，末尾字幕超过 25 秒且所有时间不超过视频时长。
- 4 段视频以一个批次处理，耗时约 4.66 秒（包含模型加载及文件哈希，不含下载、环境安装和复核）。只代表此电脑和这些短样本。
- 静音视频输出空文本和空字幕。
- 再运行跳过全部已完成样本；插入损坏 MP4 后报告错误，继续检查其余视频。
- skill 格式校验、git diff --check 通过。

## 子 agent 复核实测

用户授权后，以 `model=gpt-6-luna`、`reasoning_effort=low`、`fork_turns=none` 启动真实子 agent。只向它提供三个文字块及复核协议，没有提供合成语音的标准答案。静音样本不派发修复任务。

- 三个修复 JSON 一次通过协议校验。
- 中文转换为简体，“时间走”修为“时间轴”；数字保留，英文原句保持不变，没有翻译或扩写。
- finalize 发布四份结果，分别核验每条字幕时间与原始段落完全相同。
- 四个复核任务目录全部清除，`.test-data/repaired-results/.work/` 为空；每份结果仅包含修复 TXT、SRT、修改记录和完成标记。
- 四份完成标记记录 `reviewed=true` 及实际使用的 `gpt-6-luna / low`；全局 config.json 仍保持用户原来的默认偏好。
- 本地校验脚本 `.test-data/check_repair.py` 报告 `ALL FOUR OUTPUTS VERIFIED; INTERMEDIATES REMOVED`。该脚本用于一次性验证，会消费中间稿；重新运行需先创建并复核新的任务。
